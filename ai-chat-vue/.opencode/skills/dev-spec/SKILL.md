# 开发规范

## 基础原则

- 始终使用简体中文进行所有回复和交流
- 代码注释也使用中文（除非项目规范要求英文）
- 不说多余的客套话，描述，解决问题本身
- 用户给你一段代码或任务时，先检查当前所在目录是否处于工程项目中

## 上下文策略

1. 开发前先理清楚大致流程。细节和逻辑有疑问必须问开发者，不要自行猜测处理。
2. 整个任务实行主代理 + 多个子代理配合的结构：
   - 主代理负责整理任务框架、梳理流程、思考项目架构
   - 子代理负责执行主代理分发下来的具体任务
3. 单个窗口上下文超过 50% 时，先保存提取上下文，再开启新窗口注入上下文继续任务。
4. 原则上单个代理的上下文大小不超过 50%，单次代码生成不超过 300 行。
5. 更复杂的任务应该尝试拆分，分发给子代理执行，保证主代理上下文简洁。

## 开发详情

1. 触发条件：检测当前是否处于工程项目中。用户给你一段代码时，先检查自身所在目录。
2. 当前目录有 README.md 必须先阅读。
3. 完成某个任务后要更新当前 README.md 的任务进度。
4. 单页面代码量理论上不超过 1000 行，超过就要考虑拆分、抽离逻辑。
5. 拆分时需要用户配合，主动询问用户意见。
6. 任务完成后，要自己在浏览器中跑一遍验证结果，如果报错继续处理直至通过。

## 代码规范

1. 修改文件前先理解该文件已有的代码风格，保持一致性。
2. 使用项目已有的库和工具，不随意引入外部依赖。
3. 创建新组件时先参照已有组件的写法。
4. 开发完成后运行项目的 lint 和 typecheck 命令确保无报错。
5. 不主动提交代码，除非用户明确要求。
6. 禁止引入暴露或记录密钥、token 等敏感信息的代码。

## 沟通规范

1. 回答简洁直接，不啰嗦。
2. 需要用户决策的地方主动询问，不自行假设。
3. 使用 GitHub-flavored markdown 格式回复。
